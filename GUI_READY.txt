🎯 KEY FEATURES
═══════════════════════════════════════════════════════════════════════════════

1. AUDIO INPUT SELECTION
   • Auto-discovers all audio input devices
   • Displays device type (input/loopback)
   • Shows channels and sample rate
   • Refresh button to re-scan
   • Fallback to generic device if needed
   • ✓ Found 16 audio devices on your system

2. FREQUENCY RANGE SLIDERS
   • Min frequency slider (20 Hz - 10,000 Hz)
   • Max frequency slider (100 Hz - 20,000 Hz)
   • Real-time range display and updates
   • Constraints enforced (min < max)
   • Common presets: bass, mid, high, full spectrum
   • Defaults to full range (20 Hz - 20 kHz)

3. ANALYSIS RESULTS LOGGER
   • Large scrollable text widget (right side of GUI)
   • Displays one entry per analysis operation
   • Columns: Time | Operation | Value | Latency | Frequency Range
   • Color-coded latency:
     - Green (<15ms): Fast, good performance
     - Amber (15-30ms): Acceptable
     - Red (>30ms): Slow, potential bottleneck
   • Auto-scrolls to newest results
   • Pause/Resume button to examine results
   • Clear Log button to delete history
   • Max 1000 entries to prevent memory issues
   • Event logging for detected beats/onsets

4. PIPELINE CONTROL
   • Start Analysis button: Launches streaming pipeline
   • Stop Analysis button: Graceful shutdown
   • Status indicator: Shows Running or Idle
   • Non-blocking GUI during analysis
   • Thread-safe pipeline operation

5. PERFORMANCE MONITORING
   • Chunks Processed: Count of audio blocks analyzed
   • Avg Latency: Average time per chunk (ms)
   • Uptime: How long pipeline has been running (s)
   • Real-time updates during operation

🔌 ARCHITECTURE OVERVIEW
═══════════════════════════════════════════════════════════════════════════════

Main Thread (Tkinter GUI)
├─ Renders widgets
├─ Handles user input (device selection, sliders, buttons)
├─ Updates performance metrics
└─ Receives pipeline events via callbacks

Pipeline Thread (Daemon - Separate)
├─ AudioCaptureWorker
│  └─ Reads audio from selected device
├─ ProcessingWorkers[0-3] (4 parallel)
│  └─ Extract audio features (STFT, energy, etc.)
├─ AnalysisWorker
│  └─ Detect events (beats, onsets)
└─ RenderingWorker
   └─ Send results to GUI via event callback

Data Flow:
  Audio Device → Capture → [Queue] → Processing → [Queue] → Analysis
  → [Queue] → Rendering → [Callback] → GUI Update → Log Display

📞 SUPPORT & TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Issue: No audio devices showing
Solution: Install sounddevice (pip install sounddevice) and click Refresh

Issue: GUI freezes on Start
Solution: Selected device may be unavailable; try different device

Issue: No results appearing
Solution: Make sure audio is playing; check Pause button isn't active

Issue: High latency (>50ms)
Solution: Close other apps; reduce FFT size; increase processing workers

See docs/GUI_USER_GUIDE.md for complete troubleshooting guide
